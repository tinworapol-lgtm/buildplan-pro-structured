# Project Hub Design

## Goal

หลังยืนยัน OTP สำเร็จ ผู้ใช้เข้าสู่หน้า **โครงการของฉัน** โดยตรง เพื่อสร้าง เปิด เปลี่ยนชื่อ ทำสำเนา และจัดเก็บโครงการ โดยไม่ต้องใช้งานผ่านหน้าต่าง Account & Cloud แบบเดิม

## Scope

ระยะนี้ครอบคลุมเฉพาะ Project Hub และการจัดการรายการโครงการ:

- แสดงโครงการ Cloud ของผู้ใช้ที่เข้าสู่ระบบ
- สร้างโครงการใหม่
- เปิดโครงการเดิม
- เปลี่ยนชื่อโครงการ
- ทำสำเนาโครงการ
- ย้ายโครงการไปถังขยะ
- แสดงสถานะว่าง กำลังโหลด และข้อผิดพลาด
- กลับไปหน้า Project Hub จาก Workspace

ไม่รวม Cloud Autosave, Version History, การกู้คืนเวอร์ชัน และการลบถาวร ซึ่งเป็นระยะถัดไป

## User Flow

1. ผู้ใช้กรอกอีเมลและรหัส OTP
2. เมื่อ Verify สำเร็จ ระบบเปิดหน้า Project Hub
3. ระบบโหลดรายการโครงการของบัญชีนั้นอัตโนมัติ
4. ผู้ใช้เลือก:
   - `สร้างโครงการใหม่` เพื่อเปิดฟอร์มข้อมูลโครงการ
   - `เปิดโครงการ` เพื่อโหลดข้อมูลและเข้าสู่ Workspace
   - `เปลี่ยนชื่อ`
   - `ทำสำเนา`
   - `ย้ายไปถังขยะ`
5. ปุ่มกลับหน้าหลักใน Workspace กลับไป Project Hub เมื่อผู้ใช้เข้าสู่ระบบ

ผู้ใช้ที่ไม่เข้าสู่ระบบยังเข้า Workspace ฟรีได้ตามเดิม แต่ใช้ Local Autosave และ JSON เท่านั้น

## UI Structure

Project Hub เป็นหน้าเต็ม ไม่ใช่ modal:

- Header:
  - โลโก้ BuildPlan Pro
  - อีเมลผู้ใช้
  - ปุ่มกลับหน้าแรก
  - ปุ่มออกจากระบบ
- Toolbar:
  - หัวข้อ `โครงการของฉัน`
  - จำนวนโครงการ
  - ปุ่มรีเฟรช
  - ปุ่ม `สร้างโครงการใหม่`
- Project list:
  - ชื่อโครงการ
  - วันที่แก้ไขล่าสุด
  - สถานะ `กำลังใช้งาน` สำหรับโครงการปัจจุบัน
  - ปุ่มเปิด
  - เมนูเปลี่ยนชื่อ ทำสำเนา และย้ายไปถังขยะ
- Empty state:
  - ข้อความว่ายังไม่มีโครงการ
  - ปุ่มสร้างโครงการแรก

## Architecture

- `app-shell.js` เพิ่ม route `projects` และควบคุมการแสดงหน้า Project Hub
- สร้าง `project-hub.js` สำหรับ render รายการและจัดการ interaction โดยใช้ `BuildPlanCloud`
- `cloud-save-adapter.js` เพิ่ม `duplicateProject(projectId)` ซึ่งเรียก `POST /api/projects?action=duplicate&id=<projectId>`
- `api/projects/index.js` ทำสำเนาฝั่ง server โดยตรวจ ownership โหลด payload ต้นฉบับ และสร้าง row ใหม่ด้วย UUID ใหม่
- Account & Cloud modal เหลือเฉพาะ login/session, export และ feedback ไม่ใช้เป็นหน้ารายการโครงการหลัก

ไม่เพิ่ม Vercel Function ใหม่

## Data And Security

- Supabase `projects.user_id` เป็นเจ้าของข้อมูล
- ทุก list/load/update/archive/duplicate ตรวจ `user_id` ของ session
- ทำสำเนาสร้าง UUID ใหม่และเติมคำว่า `สำเนา -` หน้าชื่อเดิม
- Project Hub ไม่แสดง payload เต็มจนกดเปิด เพื่อลดข้อมูลและเวลาโหลด
- ผู้ใช้คนหนึ่งไม่สามารถเห็นหรือแก้ไขโครงการของอีกบัญชี

## Error Handling

- Session หมดอายุ: แสดงข้อความให้เข้าสู่ระบบใหม่ โดยไม่ล้าง Local Autosave
- โหลดรายการล้มเหลว: แสดงปุ่มลองใหม่
- เปิดโครงการล้มเหลว: อยู่หน้า Project Hub ต่อและไม่เปลี่ยน current project ID
- ทำสำเนาหรือเปลี่ยนชื่อล้มเหลว: แสดงข้อความจาก API และคงรายการเดิม
- โครงการถึง quota: แจ้งจำนวนสูงสุดและไม่สร้างข้อมูลใหม่

## Testing

- Verify สำเร็จแล้ว route ไป `projects`
- Project Hub โหลดรายการอัตโนมัติ
- เปิดโครงการแล้ว payload ถูก apply และจำ current project ID
- ทำสำเนาได้ ID ใหม่
- เปลี่ยนชื่อและ archive เฉพาะโครงการเจ้าของบัญชี
- ผู้ไม่ล็อกอินได้ `401`
- กดแผนใหม่ไม่บันทึกทับโครงการเดิม
- Quality gate และ production smoke ต้องผ่าน

## Success Criteria

- ผู้ใช้กลับมาเข้าสู่ระบบและเห็นโครงการเดิมทันที
- เปิดโครงการได้โดยไม่ต้องคัดลอก Project ID
- การบันทึกครั้งต่อไปอัปเดตโครงการที่เปิดอยู่
- ไม่มีข้อมูลของบัญชีอื่นรั่วไหล
- ผู้ใช้ทั่วไปไม่เห็น environment diagnostics หรือการตั้งค่า Stripe
